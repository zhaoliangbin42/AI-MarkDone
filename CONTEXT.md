# AI-MarkDone Product Context

This file defines the short, shared vocabulary used in product discussion, implementation, and documentation. Detailed behavior remains authoritative in `docs/FEATURES.md` and `docs/architecture/CURRENT_STATE.md`.

## User-facing vocabulary

|:--|:--|:--|

Use these names in interface copy and authored help. Existing code symbols, persisted schemas, user-authored prompt contents and custom templates are not renamed. Annotation-output `userPrompt` denotes the selected reusable prompt; Reader's user message denotes the question. Bookmark excerpts independently keep the start/end of the saved question and reply when each exceeds 500 characters.

## UI System

- **Surface**: one user-visible AI-MarkDone work area with a defined entry, owner, DOM scope, lifecycle, and responsive behavior. A Surface may be a panel, modal, anchored popover, inline host control, or extension document.
- **Surface family**: related Surfaces that share density, chrome, interaction, and responsive behavior, such as Reader, Bookmarks, Composer, or host-integrated controls.
- **Chrome**: repeated interface structure around content, including headers, footers, rows, controls, dividers, focus treatment, and feedback states. Chrome does not own feature data or platform selectors.
- **Transient UI**: short-lived contextual UI such as a popover, tooltip, toast, suggestion list, or hover action. It must have an explicit anchor, dismissal contract, focus behavior, and viewport fallback.
- **Surface profile**: a named presentation contract (`panel`, `modal`, `anchored`, or `inline`) that supplies shared chrome and lifecycle behavior without exposing low-level style flags.
- **Responsive contract**: the declared width, height, collision, scroll-owner, and narrow-viewport behavior for a Surface. It is owned by the Surface family rather than assembled from unrelated media queries.
- **Appearance snapshot**: one immutable theme-and-global-appearance value distributed to UI roots. Reader content width and Reader body font size are Reader state, not global appearance.
- **Appearance scope**: the token-injection target for an appearance snapshot: a page root, ShadowRoot, or documented light-DOM portal.
- **Surface session**: the lifecycle owner for mounting, appearance and locale updates, focus, dismissal, positioning, motion, close, and destruction of one Surface.

The complete Surface catalog, token ownership rules, and responsive contracts are authoritative in `docs/design.md`. The implementation history and current Phase 7 closeout record live in `docs/refactor/UI_SYSTEM_REFACTOR_PLAN.md`.

## ChatGPT Input Enhancement

- **Input Enhancement**: the complete optional authoring layer attached to the official ChatGPT composer. It does not replace the composer or render rich text inside it.
- **Availability switch**: `chatgptBehavior.inputEnhancement.available`, shown in Settings. Turning it off pauses every enhancement while preserving detailed preferences. The composer has no Input Enhancement entry; lower-right entry visibility is controlled separately.
- **Runtime master switch**: `chatgptBehavior.inputEnhancement.enabled`, shown in Settings and the lower-right Input Enhancement popover. Effective state is `available && enabled`; it controls entry highlighting and whether any child capability runs.
- **Enter-newline**: intercepts ordinary Enter outside lists. Cmd/Ctrl + Enter remains the send shortcut; Shift + Enter remains host-owned.
- **List enhancement**: the parent capability for CommonMark-aware list authoring. Ordered and unordered lists are independently selectable beneath it, while each list type keeps its own complete behavior set.
- **Bold shortcut**: Cmd/Ctrl + B inserts or removes visible `**` markers; it is not rich-text rendering.
- **Formula suggestions**: formula-local LaTeX snippet completion for `\\` tokens inside `$...$` or `$$...$$`.
- **Formula preview**: lightweight anchored rendering for inline and display formulas. It never rewrites or renders inside the source composer.

Both master switches preserve child values when disabled. Effective capability state is always derived from availability, runtime master, and the corresponding child switch.

## ChatGPT Content Discovery

- **Conversation content pool**: the one immutable Content Port V1 value that owns the current page/canonical document identity, typed turn identities, canonical assistant Markdown, order and per-body provenance. Consumers never merge Graph and DOM evidence themselves; a turn in the pool is available for consumption.
- **Canonical route identity**: `chatgptRoute` reads one safe token immediately after a semantic `c` or `conversation` path segment at any depth on an allowed ChatGPT page host. `/c/<id>`, `/conversation/<id>`, `/g/<scope>/c/<id>`, and other prefixed forms use the same rule; `/g/<id>` alone is not a conversation. Route identity binds a document epoch but never decides whether content exists.
- **Page identity (current)**: an in-memory, Runtime-scoped identity created before a canonical conversation ID exists, including URL-stable logged-out pages. Stable DOM rounds publish against it immediately. It is not persisted and cannot authorize bookmark persistence or cross-page navigation. A later canonical identity promotes the same projection without changing turns, bodies, projection ID or content token.
- **No-ID consumer boundary**: Toolbar, word count, Directory, Stepper, Reader, copy, formula and export consume page-identity content normally. Bookmark preparation is unavailable until the existing canonical conversation ID and URL requirements are met; it sends no save/remove request and changes no bookmark type, protocol, storage field, migration or compatibility record.
- **Conversation Content Port V1**: the stable `read / subscribe / refresh / isCurrent` Interface implemented by `ConversationContentRepository`. It publishes only `idle / syncing / ready / unavailable`; `idle` means no page document is bound, not an unsupported URL. Every ChatGPT Runtime supplies page identity before canonical identity, so a missing route ID cannot itself produce an unavailable content state. `refresh()` flushes local work and never reopens baseline admission or performs a request.
- **Content Source Adapter**: the platform driver that reads one structurally and identity-verified Graph from passive Bridge memory per conversation epoch, normalizes provider Markdown, and submits baseline evidence. It is independent of one fixed endpoint and never performs an extension-issued conversation request. Since ADR-0020 the bridge also accepts a Graph whose payload declares the current canonical conversation id when the GET URL did not carry it; payloads declaring another conversation are counted as rejected and never remembered.
- **Host Monitor**: the single ChatGPT PageIndex-backed DOM input. Structure/identity events record stable outer-slot topology immediately; eligible bodies stay coalesced behind the existing connected official action row and non-streaming guard. Native search-unit assistant-only messages with one exact assistant ID are eligible without a mounted Prompt. Each batch reads the existing conversation scroll root once before compilation to supply a coarse placement hint. Only explicit Repository admission acknowledges capture, after the proposed public snapshot passes V1 validation. Refused IDs remain dirty for a real host/lifecycle signal; there is no retry ladder or polling. A recycled connected owner's changed assistant ID invalidates its in-flight clone, while an unrelated mutation or ordinary unmount does not.
- **Host order merge**: use shared stable message/position anchors to insert a new observed range before its next shared neighbour, or after its last shared neighbour at the tail. Multiple plausible interleavings do not block hydration. Without shared/source anchors, an available batch viewport hint places the current run before retained history, or after it near the latest end, so missing total-order proof does not discard eligible bodies. This placement is provisional; later exact mounted order can correct it and repair retained historical topology. Exact identity, pair, simultaneous-owner and public V1 conflicts still reject. Numeric display positions and arrival order are never identities, and coarse placement never proves complete history.
- **Message-owned logical slot**: when the containing owner has no stable marker, its unique exact assistant ID proves a logical position; its unique contained user ID names the paired position when available. Temporary `fallback-turn-*` markers, user-only provisional owners and empty placeholders cannot create one. Exact topology identity is retained before body eligibility, so an assistant with a compatible user pair can prove a later owner-marker alias without waiting for compilation. Competing live ownership and conflicting pairs reject atomically; an available placement hint may repair inconsistent retained topology without changing message identity. Existing semantic turn identity is retained and late prompts enrich the same body.
- **Host admission receipt**: internal Repository result containing current state, admitted assistant IDs and a rejection reason. An idempotent body is admitted even when no snapshot is published. Only admitted complete pairs enter the Monitor's remount-skip set. Content Port V1 remains unchanged.
- **Source provenance**: `{ authority, fidelity, producer }` attached to canonical Markdown. `source`, `hybrid`, and compiler-verified `host` turns are all consumable; provenance describes origin, not a consumer block.
- **Coverage**: the maintained cache publishes only dense `complete` snapshots — every admitted turn has a complete, dense body. Streaming, debounce and compilation are internal timing details; an unfinished turn is simply not in the cache yet.
- **History status**: `unknown | partial | get | complete`. Ordinary mounted-DOM evidence is `partial`; an accepted website GET seed is `get`, not proof that every historical body was mounted. `complete` remains for independently proved/legacy consumers; entry or scrolling does not manufacture it.
- **Semantic Content Module**: the provider-neutral `compile / resolve / project` Interface that turns canonical Markdown into an immutable AI-MarkDone document, UTF-16 half-open source spans, plain text, Reader units/outline, and canonical Markdown projections. DOM and parser-library ASTs do not cross this Interface.
- **Content Surface Adapter**: the driver Interface that captures a same-message, non-streaming native selection and emits typed identity, revision tokens, W3C-style TextQuote evidence, and parser-backed source atoms such as authoritative formula TeX. Range, Element, and host selectors remain inside the driver.
- **Surface Projection**: the only service seam that joins surface evidence to canonical source. It validates content and materialization revisions; the interaction controller re-captures the current surface token before reuse. Stale, ambiguous, reconstructed, or unproven mappings fail open.
- **Reader content source**: the sole projection from a published conversation snapshot to `ReaderItem[]`. Passive queries call `readCurrentReaderContent`; real user commands call `collectFreshReaderContent`, whose one no-argument confirmation policy is owned by the source rather than its callers.
- **Reader content source status**: the additive `ready / unavailable / target-unresolved` state plus coverage and source quality. ChatGPT copy/bookmark/export read the maintained cache and reject only missing targets or unsupported surface proof.
- **Source revision**: the ephemeral conversation/content-token identity used to reject stale asynchronous UI work. It is not persisted in bookmark, export, annotation, or Reader schemas.
- **Discovery diagnostics snapshot**: the one read-only aggregate of discovery-chain facts (basis, gate state, deferred count, compiler rejection counts, bridge counters). It is a troubleshooting surface, never a content source, and never carries message bodies, prompts, or personal content. Parser rejections and admission/order rejections are separate counters.
- **Bridge diagnostics**: the page bridge's own counters served through the `diagnostics` request type: eligible GET observations, accepted/rejected graphs, published captures, LRU evictions, byte-cap skips, parse failures, and the held graph count.
- **Conversation Reader binding**: the cache subscription that keeps the in-page Reader aligned with published revisions. It never discovers DOM turns or starts a second acquisition path.
- **Materialization**: the host-controlled act of mounting a typed conversation turn into the current DOM window. It may add or remove complete group anchors or an assistant-only surface projection, but it never changes obtained content or order. A complete assistant-only body may be admitted under its stable assistant identity and host slot; its missing Prompt is not fabricated and a later real prompt remount can update the pair.
- **Conversation Surface**: the single production Frame that atomically joins the Repository snapshot with current PageIndex facts and classifies obtained, pending-surface, and unmounted entries. Directory, Toolbar and Stepper subscribe only to this Frame.
- **Conversation Materialization Port V1**: the content-runtime-only compatibility projection derived from Conversation Surface for typed targets, connected anchors, a materialization token, and bounded locate. It does not own state or expose body text.
- **Retired conversation projections**: the former Discovery Coordinator, Conversation Index, and standalone Conversation Materialization modules no longer exist. Their lifecycle, join, and anchor responsibilities are owned respectively by Runtime, Repository/PageIndex, and Conversation Surface; compatibility consumers receive a Materialization Port derived from the current Surface Frame rather than a second store.
- **Round identity**: typed `userMessageId`, `assistantMessageId`, and graph round/node aliases. Prompt text and DOM-local position are presentation data, never identity. Window-local fallback-turn-* search keys remain DOM selectors only; semantic turn IDs derive from stable explicit/user/assistant identities.
- **Lifecycle signal**: initial Runtime synchronization, History `pushState`/`replaceState`, `popstate`, `hashchange`, `pageshow`, a PageIndex host fact, or a validated passive-Graph capture. The Runtime first synchronizes identity/fences stale work, then admits evidence and lets Conversation Surface publish one Frame; there is no content RouteWatcher, polling loop, POST observation, or second discovery path. `pageshow` and the Settings retry action may additionally re-arm one bounded peek while the baseline gate is open (ADR-0020); an accepted Graph closes the gate permanently for its epoch, and consumer `refresh()` never re-arms it.
- **Content token**: the immutable message-pool snapshot token. It changes when obtained order/identity, Markdown, or provenance changes. Page→canonical identity promotion, state transitions, URL text changes, and DOM remounts do not manufacture it; a true conversation/projection switch creates a new pool boundary.
- **Materialization token**: the current typed-target-to-DOM projection revision. Host virtualization/remounting may change it without changing the content token.
- **Surface token**: the identity of the concrete rendered content root used to capture interaction evidence. Replacing that root invalidates an old selection even if content and materialization tokens are unchanged.

## ChatGPT Atomic Selection Copy

- **Atomic Markdown shortcut**: `chatgptBehavior.atomicMarkdownCopyShortcut` is the only ChatGPT direct-selection Markdown copy control. It is `none`, `mod-c` (`Ctrl/Cmd+C`), or `mod-shift-c` (`Ctrl/Cmd+Shift+C`); fresh installs default to `mod-shift-c`, while legacy `atomicMarkdownCopy` values migrate to `mod-c` or `none`.
- **Reader-compatible visual atomic selection**: the official ChatGPT page uses the same rendered-unit range and selected-effect semantics as Reader for code, formulas, tables, images, headings, lists, and blockquotes. Plain paragraphs and inline formatting wrappers are not promoted to separate visual atoms; this visual layer never becomes a Markdown source.
- **Keyboard-only exit**: ChatGPT direct selection no longer creates a copy button or inverse action. Ordinary, structured, and formula selections use Surface Projection to recover canonical source Markdown. The old strict atomic DOM converter remains only for legacy composition roots that have no canonical content/materialization ports; it is never revived after a production semantic projection rejects evidence. Invalid, editable, streaming, cross-message, ambiguous, stale, reconstructed, or DevTools-consumed configured shortcuts fail closed without publishing visual text; the host remains untouched when the shortcut is disabled or no canonical ports exist.

## Reader Annotations (v1 shipped)

- **Annotation document**: one verified ChatGPT conversation identified by `{ platform: 'chatgpt', conversationId }`. Its title and last URL are display/navigation hints, never identity.
- **Annotation target**: the selected source inside a canonical assistant message. `assistantMessageId` is the required semantic identity; round/user IDs and position are supporting or presentation data.
- **Re-anchoring**: restoring a saved selection after Reader content or DOM structure changes. v1 accepts only a validated exact match through DOM/atomic selectors, TextPosition, or TextQuote; an ambiguous match becomes `unanchored`.
- **Pending annotation navigation intent**: a short-lived background-owned request bound to a newly created ChatGPT tab. After the tab exposes a verified conversation identity, it opens Reader at the target assistant message and focuses the annotation. It is navigation state, not annotation data or conversation identity.
- **Annotation persistence preference**: `reader.persistAnnotations`, an explicit opt-in setting shared by Reader Settings and the annotation manager. It controls whether newly created ChatGPT annotations enter the profile-local per-conversation bundle. Existing durable annotations are always read, displayed, edited, and deleted normally; disabling the preference only keeps future annotations in the current page runtime.
- **Annotation excerpt**: the manager’s source preview keeps up to 50 Unicode characters at each end and replaces omitted middle content with one ellipsis.
- **Bulk annotation edit**: a simple manager selection mode with select-all for visible rows and one confirmed batch deletion; it is not a separate notes workspace or export surface.


## Management panel presentation

- **Settings information group**: the five Feature overview/Changelog/FAQ/About the author/Feedback links below a divider share Settings' scroll owner with the eight categories. Mappamory and Buy Me Coffee are the two fixed bottom entries.
- **Workspace full screen**: a transient visual-viewport layout controlled beside Close in the panel's upper-right corner, without a separate title bar or footer. It reuses the current surface and retains view state while toggling; close clears the mode. It has no browser-fullscreen request or stored preference and is separate from Reader's persisted default opening size.
- **Send reading-position session**: a user-send-scoped, best-effort page behavior. Capture before send-button focus or Input Enhancement's explicit focus; repeated send signals keep the initial visual anchor. Connected anchors use their current geometry, including zero movement, while disconnected or absent anchors fall back to the saved position; reverse layouts subtract the change in scrollable extent to compensate their shifting negative coordinate range. The existing 90-second bound and user interactions/navigation end the session; successful corrections do not consume a fixed attempt budget. Synthetic Enter after explicit send arming does not cancel that session.
